Mission control for coding agents.

Forecrew installs into a repository and makes the agents you already use work in stages: a purpose with numbered criteria, a contract, the change, a proof, four reviewers, a pull request. Every stage is a file. A hook refuses the next one until the last is complete.

git clone https://github.com/yantadeu/forecrew.git && ./forecrew/install.sh /path/to/repo

Claude Code, Cursor, Codex and GitHub Copilot. Bash and the Python standard library. Apache 2.0, no account.

What it changes

A single agent is fast and forgets. The purpose lives in a conversation that gets summarized, "done" means it says so, and the context that wrote the code reviews it.

Without itWith Forecrew
The goal drifts when the conversation is summarized.It lives in 00-purpose.md, with criteria AC-001, AC-002… that every stage cites.
The agent picks between two readings on its own.It writes [NEEDS CLARIFICATION] and asks you, one question at a time. Nothing is built on a guess.
"Tests pass."The tester reverts the fix and shows each test failing without it. Lint, build and tests run on the exact diff before any review.
One context checks its own work.Contract, security, QA and product reviewers run in parallel, each in a clean context, on the same diff.
Decisions you never saw.Every ruling taken without you goes in ledger.md, with what it costs if wrong.
Each task starts from zero, and cleaning it up deletes what it learned.Learnings, kept decisions and one entry per finished task outlive the cleanup, and the next task searches them before its contract.
"Done."Done means a pull request exists, or you closed the task yourself.
Watching five terminals.One page lists every task of every worktree. What needs you is at the top, and you can answer it there.

What it remembers

    
.work/CSV-12/ is deleted when the task is cleaned up. What is worth keeping leaves it first, and only with your ok. It goes into plain markdown files you commit and review like code.

  

  

    

      
FileWhat it keepsWho reads it

      
        
LEARNINGS.mdA fact a task proved that the code does not show, tagged.Each reviewer loads only its tags.

        
DECISIONS.mdRulings from the ledger that someone will later ask "why?" about, with what each costs if wrong.The refiner. A task that would break one becomes a question for you.

        
TASKS.mdOne entry per finished task: purpose, criteria, pull request.The triage, so "didn't we do this already?" has an answer.

        
docs/brain/Optional. Linked pages for what the code does not say: domain concepts, a glossary, who owns what, external systems.Anyone. /brain ask answers with citations; the folder opens as an Obsidian vault.

      
    

  

  

    
learnings.py --search ranks all four by the words you give it, or by meaning if you set an embeddings command. /brain add distills a link, a file or a note into pages and never copies a secret or someone's contact. /brain lint lists pages the code now contradicts, broken links and facts gone stale. Point the brain at a folder outside the repository and it is your own notes instead of the team's.

  






  

    
The dashboard

    
A local page, served by a small standard-library server, behind a token. It reads the same files and the hook's event log. Nothing leaves the machine.

  

  

    
    
    
    
    
    
    
  






  

    
Where it runs

    
It is not a terminal or an app. It is a directory in your repository (.claude/: agent definitions, commands, one hook, a few scripts) plus that page. So it runs in a plain shell, tmux or zellij panes, iTerm, Warp, Ghostty, the terminal inside VS Code or JetBrains, and inside apps that lay out many agent terminals: each session gets the same stages and gates, and one dashboard lists them all.

Install

  
You need git, bash and Python 3. A task tracker is optional: a sentence is enough to start.

  
    
    
  1. Get the kit and install it into your repository. Existing AI configuration is kept unless you ask to replace it.

    git clone https://github.com/yantadeu/forecrew.git
./forecrew/install.sh /path/to/repo
    2. 
    
  2. Open a session there and answer a short interview: tracker, docs, stack, how checks run.

    cd /path/to/repo && claude
/flow-setup
    3. 
    
  3. Start a task with a ticket id, a link or plain words.

    /task add CSV export to the report page
    4.
